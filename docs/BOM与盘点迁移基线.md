# BOM 与盘点迁移基线

## 安全边界

- `cost` 旧系统只作为只读参考源，不由新模块连接。
- `V024__cost_bom_inventory_foundation.sql` 只定义目标 SaaS 的新表，不读取、更新或删除旧系统数据。
- 第三方系统数据必须经 `tql-store-integration` 同步，不允许成本服务直接保存生产密钥。
- 所有业务查询必须包含 `tenant_id`；门店对象还必须校验属于当前租户。

## 第一批迁移范围

- BOM：草稿创建、版本化物料明细、按门店查询。
- 盘点：盘点任务创建、按门店查询、不可变物料快照和幂等实盘记录的数据基础。
- 权限：商家端 BOM 与盘点查询、新建权限。

## 暂未迁移

- BOM 编辑、审核、发布、复制、半成品展开、成本计算和导入导出。
- 盘点库位、人员分配、快照生成、录入、提交、复盘、审核、结算和关账。
- 金蝶物料、价格和库存同步。
- 哗啦啦菜品与销售同步。
- 旧系统历史数据搬运与校验。

## 旧数据映射原则

| 旧字段 | SaaS 字段 |
| --- | --- |
| `shopCode` | `sys_store.id` 与外部门店编码映射 |
| `deptCode` | 商家组织主键与外部部门编码映射 |
| `stapCode` | `cost_material.id` 与 `external_material_code` |
| `foodCode` | `cost_dish.id` 与 `external_dish_code` |
| 旧 BOM 主键 | 独立迁移映射表，不直接复用为新主键 |
| 旧盘点编码 | 独立迁移映射表，不作为租户隔离依据 |

## 后续验收门槛

1. 先确认物料、菜品、门店和单位的唯一标识。
2. 抽取代表性 BOM，验证物料数量和单位换算。
3. 在本地匿名数据集上验证跨租户、跨门店访问被拒绝。
4. 新旧盘点双轨对账至少一个完整盘点周期。
5. 未达到对账门槛前，不允许将旧系统切换为只读或停止服务。
