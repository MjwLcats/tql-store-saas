# App API 地址自动检测设计

## 目标

开发者在家庭和公司使用不同电脑运行 HBuilderX 时，不再手动修改 iOS 调试基座中的 Gateway IP。每台电脑在编译 App 时自动选择自己的局域网 IPv4，并生成 `http://<LAN_IP>:8080` 作为接口基址。

## 方案

Vite 配置在构建阶段读取本机网络接口，保留 RFC 1918 私有 IPv4，排除回环、WSL、Docker、Hyper-V、VMware、VPN 等虚拟接口，并优先选择名称类似 Wi-Fi、WLAN 或 Ethernet 的物理接口。选中的地址通过 Vite 编译常量 `__TQL_API_BASE_URL__` 注入 App，`config/app.js` 不再保存任何具体开发电脑 IP。

若自动选择不符合预期，开发者可在启动 HBuilderX 前设置 `VITE_API_BASE_URL`，例如 `http://10.0.0.8:8080`。配置值必须是合法的 HTTP(S) 源地址；错误配置会在编译阶段直接失败。无法识别局域网地址时回退到 `127.0.0.1`，同时构建控制台会打印最终接口基址，便于发现问题。

## 验证

- 使用模拟网络接口验证物理网卡优先于虚拟网卡。
- 使用环境变量验证手动地址拥有最高优先级。
- 执行 Vite/uni-app 构建，确认注入常量被替换且控制台打印最终地址。
- 在两台开发电脑上分别运行到同一部 iPhone，确认地址随编译电脑变化。
